**Institution:** National Open University of Nigeria (NOUN), Abuja

## 1. Project Overview

This software prototype implements an experimental machine-learning methodology for screening health insurance claims. By treating high-dimensional categorical claim attributes as semantic "tokens" within claim "sentences", the system trains a **Gensim Word2Vec** Skip-Gram model to learn dense vector embeddings of patient demographics, clinical specialties, and claim submission channels. These representations are combined with standardized financial and temporal features to train a **class-balanced Logistic Regression** classifier.

An equivalent **One-Hot Encoded baseline** is trained simultaneously on identical data partitions to provide an objective, transparent benchmark.

> **Academic & Operational Disclaimer:**  
> This system is an academic research prototype. Predictions generated by the models are statistical screening signals indicating elevated risk characteristics and do **not** constitute legal, operational, or clinical proof of fraud. All flagged claims require thorough human review by qualified healthcare auditors prior to adjudication.

## 3. Methodological Pipeline

1. **Data Ingestion & Integrity Auditing**:
   - Supports `.xlsx` and `.csv` files.
   - Identifiers (`ClaimID`, `PatientID`, `ProviderID`) are excluded to avoid overfitting and preserve privacy.
   - Target leakage variables (`Cluster` and post-adjudication `ClaimStatus`) are excluded.
   - High-cardinality fields (`DiagnosisCode`, `ProcedureCode`) are excluded from initial Word2Vec tokenization.
2. **Feature Engineering**:
   - Categorical fields tokenized: `PatientGender`, `ProviderSpecialty`, `PatientMaritalStatus`, `PatientEmploymentStatus`, `ClaimType`, `ClaimSubmissionMethod`.
   - Numerical fields standardized: `ClaimAmount`, `PatientAge`, `PatientIncome`, `ClaimYear`, `ClaimMonth`, `ClaimDayOfWeek` (derived from `ClaimDate`).
3. **Strict Separation of Train and Test Partitions**:
   - Stratified 80/20 train/test split (`random_state=42`).
   - Word2Vec vocabulary, numerical `StandardScaler`, and one-hot encoders are fitted **strictly on training records only**.
4. **Classification & Class Balancing**:
   - Scikit-learn Logistic Regression with `class_weight="balanced"` to address the severe minority class imbalance (approx. 6% fraud prevalence).

## 4. Benchmark Evaluation Results (Held-Out Test Split)

Evaluated on 900 held-out test claims (54 fraud, 846 legitimate):

| Metric | Word2Vec + Logistic Regression | One-Hot Baseline + Logistic Regression | Description |
| :--- | :---: | :---: | :--- |
| **Accuracy** | **95.00%** | **95.00%** | Overall proportion of correctly identified claims |
| **Recall (Fraud)** | **98.15%** | **96.30%** | Captures 53 of 54 actual fraud cases (Word2Vec) |
| **Precision (Fraud)** | **54.64%** | **54.74%** | Trade-off yielding approx. 44 false-positive review cases |
| **F1-Score (Fraud)** | **70.20%** | **69.80%** | Harmonic mean of precision and recall |
| **ROC-AUC** | **0.9926** | **0.9915** | High discriminative capacity across thresholds |
| **Learned Vocabulary** | 22 tokens | 17 one-hot categories | Compact categorical domain space |

*Note: High laboratory test scores reflect the properties of this specific benchmark. Word2Vec and One-Hot Encoding exhibit comparable performance due to the low-cardinality nature of the categorical attributes.*

## 5. Installation and Setup (Windows & macOS/Linux)

### Prerequisites
- Python 3.10, 3.11, or 3.12 installed.
- Git (optional).

### Step 1: Clone or Open Project Directory
```powershell
cd c:\Users\LULU\Downloads\healthcare_fraud_detection_app
```

### Step 2: Create and Activate Virtual Environment (Recommended)
**Windows (PowerShell):**
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

### Step 3: Install Required Dependencies
```powershell
pip install -r requirements.txt
```

## 6. How to Launch the Application

Start the Streamlit web application locally:

```powershell
python -m streamlit run app.py
```

The application will open automatically in your browser at `http://localhost:8501`.

### CLI Model Training (Optional)
You can also retrain and evaluate the models via the command line:
```powershell
python train_model.py --data "data/Health Insurance Fraud Claims.xlsx"
```

### Running Automated Test Suite
To verify all validation rules, date feature derivation, and pipeline logic:
```powershell
python -m pytest tests/
```

## 7. Interactive Pages in Web Application

- **Home**: Research context, NOUN institutional affiliation, prototype overview, and workflow guide.
- **Dataset Upload & Inspection**: Upload new `.xlsx` / `.csv` datasets, view row counts, class distributions, and missingness audits.
- **Model Training**: One-click training with real-time progress steps, vocabulary token viewer, and feature exclusion disclosures.
- **Evaluation Results**: Metric comparison cards, dynamic confusion matrices, ROC curves, and downloadable CSV/JSON evaluation summaries.
- **Screen Single Claim**: Form-based screening for individual claims with probability scoring and downloadable review record.
- **Batch Screening**: Upload unlabelled batch claim files, compute screening flags and risk scores, and download complete audited CSVs.
- **About & Limitations**: Detailed methodological review, vocabulary constraints, and privacy ethics.
